# `@relax/md-editor`

查阅时机：改 markdown 编辑器包，或改 `app/mdplayground` 测试页时。包怎么导出、开发时读源码还是读 `dist`，见 [workspace-package.md](workspace-package.md)。这篇只记这个包比那份通用约定多出来的部分。

## 现在有什么

包在 `packages/md-editor`，包名 `@relax/md-editor`。对外从 `src/index.tsx` 导出 `MdEditor`、`DocJson`、`EditorCommand`、`Keybindings`、`MdEditorMode`、`MdEditorTheme`、`MdEditorThemeTokens`、`MdEditorThemes`。不导出 `EditorCore`、`createEmptyDocJson`、`markdownToDocJson` 和 `docJsonToMarkdown`。

组件本体在 `src/MdEditor.tsx`。它把 `EditorCore` 挂到内部节点上，卸掉时 `destroy()`。不传 `value` 时非受控，初始文档是内部的 `createEmptyDocJson()`。可选 `value` / `onChange`：只有文档变化才通知；记下刚通知出去的那份对象，父组件把同一引用传回来时不 `setValue`。不支持使用中途从非受控改成受控。`placeholder` 默认 `请输入...`，写成外壳 CSS 变量 `--md-editor-placeholder`。`mode` 是 `'edit' | 'read'`，默认 `'edit'`。切换不重建 `EditorCore`。可选 `className` 接到外壳 class 后面，可选 `style` 写在主题变量之后，同名项以传入的为准。

编辑器内核在 `src/editor/`。`marks/` 还没有。插件在 `src/editor/plugins/`：`inputRules.ts`、`keymap.ts`、`placeholder.ts`。

节点规格在 `src/editor/nodes/`，一种节点一个文件：`doc.ts`、`paragraph.ts`、`heading.ts`、`blockquote.ts`、`horizontalRule.ts`、`bulletList.ts`、`orderedList.ts`、`listItem.ts`、`text.ts`。`nodes/index.ts` 按这个顺序把规格收成一张表，`doc` 排第一，然后是 `paragraph`、`heading`、`blockquote`、`horizontal_rule`、`bullet_list`、`ordered_list`、`list_item`、`text`。`schema.ts` 只用这张表 `new Schema`。输入规则、快捷键、Markdown 往返、NodeView 不放进节点文件。

`paragraph.ts`、`heading.ts`、`blockquote.ts`、`horizontalRule.ts`、`bulletList.ts`、`orderedList.ts`、`listItem.ts` 和 `text.ts` 同时导出该节点的 JSON 类型。没有 attrs 的节点不写 `attrs`。`paragraph` 和 `heading` 没有子节点时 JSON 里没有 `content`，所以这个字段可选。`blockquote` 没有 attrs，`content` 必有，至少一块。`horizontal_rule` 没有 attrs，也没有 content。`bullet_list` 没有 attrs，`content` 必有，至少一项。`ordered_list` 的 `attrs.order` 必有，默认 `1`，`content` 同样至少一项。`list_item` 没有 attrs，`content` 必有，第一块是段落，后面可以再跟块。`list_item` 不进 `BlockJson`。`heading` 的 `attrs.level` 必有，默认 `1`。`text` 的 `text` 必有。

`src/editor/types.ts` 把节点 JSON 收成三层。`InlineJson` 现在只有 `TextJson`。`BlockJson` 是 `ParagraphJson | HeadingJson | BlockquoteJson | HorizontalRuleJson | BulletListJson | OrderedListJson`。`DocJson` 是 `type: 'doc'`，`content` 是一块或多块 `BlockJson`（`[BlockJson, ...BlockJson[]]`），空数组过不了类型检查。`DocJson` 放在这里，是因为它引用 `BlockJson`；`doc.ts` 不再写一份。加一种块或行内节点时，在节点文件里写规格和 JSON 类型，再把它放进 `BlockJson` 或 `InlineJson`。运行时校验仍在 `nodeFromJSON`。`toJSON()` 的返回值是 `any`，`getValue`、`createEmptyDocJson` 和 `markdownToDocJson` 各有一处断言成 `DocJson`。

现在九种节点：`doc` 的 content 是 `block+`，`paragraph` 和 `heading` 的 content 都是 `inline*` 并属于 `block`，`heading` 还有 `defining: true`。`blockquote` 的 content 是 `block+`，属于 `block`，`defining: true`。`horizontal_rule` 是叶子块，属于 `block`，没有 content。`bullet_list` 和 `ordered_list` 的 content 都是 `list_item+`，属于 `block`。`ordered_list` 有 `attrs.order`。`list_item` 的 content 是 `paragraph block*`，`defining: true`，不属于 `block`，只能出现在列表里。`text` 属于 `inline`。

`src/editor/json.ts` 的 `createEmptyDocJson()` 用 schema 造一个 doc，里面一个空 paragraph，再 `toJSON()`。空文档的 JSON 是 `{ type: 'doc', content: [{ type: 'paragraph' }] }`。编辑器状态、`value` / `onChange`、`getValue` / `setValue` 都是这份 `DocJson`。`markdownToDocJson` / `docJsonToMarkdown` 只在导入和导出时用，`EditorCore` 不调用它们。空串得到一个空段落。`heading_open` 变成 heading，level 取标签数字；`paragraph_open` 变成 paragraph。行内只收 `text`，加粗等 mark 先丢掉。`hr` 变成 horizontal_rule，原文是 `---`、`***`、`___` 或更长的一串都进这个节点。`blockquote_open` 到 `blockquote_close` 递归解析里面的块，得到 blockquote。里面还不认识的围栏、HTML 整段丢掉，段落不抬出来；丢掉后引用里没有块时补一个空段落。`bullet_list_open` 和 `ordered_list_open` 各自收到对应列表，项内再递归解析。有序列表的 `order` 取 token 的 `start`，缺省、不是大于等于 1 的整数时用 `1`。项里没有块，或第一块不是段落时，前面补一个空段落。`- [ ]` 仍是普通文字，任务列表留到后面。Setext 进来也是 heading，出去一律 ATX：`#` 重复 level、一个空格、再是文字。横线一律序列化成 `---`。顶层块与块之间一个空行，不加结尾换行。空段落序列化成空串。引用序列化时先把子块用空行接起来，再给每一行加 `> `：两段是 `> 甲`、`> `、`> 乙`，嵌套是 `> > 内`，引用里的标题是 `> # 标题`，引用里的横线是 `> ---`，引用里的列表是 `> - 甲`。无序列表一律 `- `，不管进来时是 `+` 还是 `*`。有序列表从 `order` 起递增写出，`1)` 进来后出去写成 `1. `。项与项之间一个换行。项内第一块接在标记后面；后面如果是子列表，续行缩进标记那么宽再接上；如果是别的块，中间空一行再同样缩进。顶层列表仍是一块，和前后块之间一个空行。解析结果再过一次 `nodeFromJSON`。这两个函数不从包入口导出。

`src/editor/EditorCore.ts` 是类，不从包入口导出。构造收 `mount`、可选 `initialValue`、`onChange`、`keybindings`、`mode`。缺省文档用 `createEmptyDocJson()`。`getValue()` 返回断言后的 `DocJson`。`setValue(json)` 用共用的 `createEditorState` 建一份新 state 再 `updateState`，选区和新的撤销栈都从头算。`setKeybindings` 用 `state.reconfigure` 只换命令 keymap，同一份 `history()` 留着，撤销栈还在。`setMode` 也走 `reconfigure`，文档和选区留着。`editable` 在编辑态为 true，阅读态为 false，DOM 上是 `contenteditable`。阅读态打不进字，也不走 `onChange`。`focus()` 调用 `view.focus()`。`destroy()` 调用 `view.destroy()`。自定义 `dispatchTransaction` 在 `docChanged` 时调用 `onChange`；`setValue` 不走这条路径。

`src/editor/reactNodeView.ts` 是自定义节点和 mark 的 React 视图，不进 `schema.ts`，不挂 `createEditorPlugins`，不从包入口导出。节点用 `createReactNodeView(Component, options)` 挂到 `nodeViews`，mark 用 `createReactMarkView(Component)` 挂到 `markViews`。每个视图自己 `createRoot`。可编辑正文是单独的 `contentDOM`，组件里用 `NodeViewContent` 占槽；工厂返回前 `flushSync` 把槽画出来再把 `contentDOM` 挂进去。`className` 和 `data-*` / `aria-*` 写到 `contentDOM` 上。`update` 只在节点类型变了时返回 false；节点和 decorations 还是原来的引用就跳过 React。`ignoreMutation` 忽略壳层和 `contentDOM` 自己的属性变更，不忽略选区和正文内部变更。`stopEvent` 把 `contentDOM` 里的事件、拖拽和剪贴板交给编辑器，壳层上的按钮和 `[data-node-view-stop-event="true"]` 拦住。节点 `updateAttributes` 走 `setNodeMarkup`。mark 的 `updateAttributes` 只改这个视图所在的那一段。第 5 期的 mark 不走这里。测试在 `src/editor/reactNodeView.test.ts`，用 `src/editor/testDom.ts` 里一份只够这次用的 DOM。

`createEditorState` 和 `createEditorPlugins` 是构造和 `setValue` 的同一条路。编辑态插件顺序：`history()`、块输入规则、命令 keymap、分隔线的 Enter、`keymap(baseKeymap)`、占位装饰。阅读态只有占位。阅读态卸下 `history` 插件后撤销栈丢掉，切回编辑态同一实例重新 `init`，栈是空的。阅读态调用 `setKeybindings` 只记下绑定，回到编辑态再生效。阅读态也不挂输入规则和命令 keymap。`baseKeymap` 负责 Enter、Backspace，不进命令表。命令 id 是 `undo`、`redo`、`paragraph`、`heading1`…`heading6`、`bulletList`、`orderedList`。默认键是 `undo` → `Mod-z`，`redo` → `Mod-Shift-z` 和 `Mod-y`，`paragraph` → `Mod-Alt-0`，`heading1`…`heading6` → `Mod-Alt-1`…`Mod-Alt-6`，`bulletList` → `Mod-Shift-8`，`orderedList` → `Mod-Shift-7`。后两个用 `wrapInList` 把当前块包进对应列表。`keybindings` 按命令给键数组：省略的命令用默认键，传入的数组整份替换该命令（空数组表示没有键）。`Mod-` 由 `prosemirror-keymap` 区分 Cmd / Ctrl。行首 `# ` 到 `###### ` 用 `prosemirror-inputrules` 的 `textblockTypeInputRule` 把当前文本块改成对应 level 的 heading，井号和空格不留在正文里。行首 `> ` 用同一插件里的 `wrappingInputRule` 把当前文本块包进 blockquote，`>` 和空格不留在正文里；紧挨着上一个引用时并进去。引用没有单独快捷键。引用里的空段落按 Enter 走 `baseKeymap` 的 `liftEmptyBlock`，把该段抬出引用；引用里没有别的块时引用消失。有字的段落按 Enter 仍在引用里拆成下一段。光标旁的 `>` 不写进正文。行首 `- `、`+ ` 或 `* ` 用 `wrappingInputRule` 包进 `bullet_list`，紧挨着上一个无序列表时并进去。行首 `1. ` 这类包进 `ordered_list`，`order` 取这个数字；只有上一个有序列表的起始号加项数等于刚输入的数字时才并进去。一个 `*` 加空格不会抢 `*** ` 的分隔线。整段恰好是至少三个 `-` 或至少三个 `*` 时，后面再输入空格，或在段尾按 Enter，才把这一文本块换成 horizontal_rule。空格和回车不留在正文里。四个及以上同样算。`___`、段里还有别的字、光标不在段尾时按 Enter，都不换。父节点不能在这一位放下横线时也不换，所以列表项里的第一段保持段落。这一块已经是父节点最后一块时，横线后面补一个空段落，光标放进去；后面还有块就不补，光标到下一块开头。解析进来的横线后面不补段落。分隔线没有快捷键。Enter 先走横线，对不上再走 `splitListItem`：有字的列表项拆成下一项，空项交给后面的 `baseKeymap`，由 `liftEmptyBlock` 抬出列表。嵌套列表里末尾的空项仍由 `splitListItem` 拆开外层项。对不上再交给 `baseKeymap`。列表缩进留到后面。

占位插件在文档恰好一个空段落时给该段加 class `mded-empty`。我们自己加的类都以 `mded-` 开头。视图通过 `attributes.class` 再加根类 `mded`，基座的 `ProseMirror` 仍在。文案不进插件，由 `base.css` 的 `.mded p.mded-empty::before` 读 `--md-editor-placeholder`，字色读 `--md-editor-placeholder-color`。

运行时依赖已经声明。和 `app/web` 对齐的是 `prosemirror-model`、`prosemirror-state`、`prosemirror-view`、`prosemirror-commands`、`prosemirror-keymap`、`prosemirror-history`。另外有 `prosemirror-inputrules`（`^1.7.0`）、`prosemirror-schema-list`（`^1.6.1`）和 `markdown-it`（`^14.3.3`）。schema 用 `prosemirror-model`，EditorCore 用 `prosemirror-state`、`prosemirror-view` 和 `prosemirror-history`，keymap 插件用 `prosemirror-commands` 和 `prosemirror-keymap`，标题、引用和列表的输入规则用 `prosemirror-inputrules`，列表的拆项和 `wrapInList` 用 `prosemirror-schema-list`，导入导出用 `markdown-it`。这些包写在 `tsdown.config.mjs` 的 `deps.neverBundle` 里，和 `react`、`react-dom` 一样不打进 `dist`，保持为这个包的直接依赖，产物里留下 `import`。`markdown-it@14.3` 没有类型声明，包内 `src/markdown-it.d.ts` 只声明这次用到的构造、`parse` 和 `attrGet`。`prosemirror-tables`、`mermaid` 还没加。

`src/editor/state.test.ts` 用 `node --experimental-strip-types --test` 打在 `createEditorState` 上，不挂视图。`src/editor/heading.test.ts` 打 Markdown 往返、标题输入规则和 `Mod-Alt` 键。`src/editor/blockquote.test.ts` 打引用往返、`> ` 输入规则和空段 Enter 拆回。`src/editor/horizontalRule.test.ts` 打横线往返，以及三个及以上 `-` / `*` 后的空格和段尾 Enter。`src/editor/list.test.ts` 打无序和有序的往返、行首标记、续号、Enter 拆项和空项退出、`Mod-Shift-8` / `Mod-Shift-7`。被测试加载的相对 import 带 `.ts` 后缀，`tsconfig.json` 打开了 `allowImportingTsExtensions`。测试文件参与本包 `tsc`。`node:test` 和 `node:assert/strict` 的类型在 `src/node-test.d.ts`，只声明测试里用到的函数。包脚本是 `pnpm --filter @relax/md-editor test`。

测试页在 `app/mdplayground`，包名 `@relax/mdplayground`。页面自己有一份壳层主题，变量前缀是 `--pg-`，数值和编辑器主题相同，暗色正文除外，样式表不互相引用。壳是三块：左侧侧栏、右侧顶栏、顶栏下面的主区域。侧栏放模式按钮，显示当前是编辑还是阅读，收起时按钮跟着藏起来。后面的 playground 控制也放这栏。侧栏底色是 `--pg-surface-2`，顶栏和主区域是 `--pg-bg`。亮色里 `--pg-bg` 和 `--pg-surface` 都是白色，侧栏不用 `--pg-surface`。侧栏和右侧之间没有分割线。`shell.css` 用 `@import "tailwindcss"`，再用 `@theme inline` 把 `--pg-*` 映成 `app`、`sidebar`、`surface`、`fg`、`border`。`--pg-*` 只写在 `[data-theme]` 上，所以同一组映射在这个选择器上再写一遍，工具类才能跟着主题变。`surface-active` 没有现成变量，用 `color-mix` 把 `--pg-surface-2` 混一点 `--pg-text`。`fg-bright` 没有更亮的一档，映到 `--pg-text`。顶栏的收起和主题用 `src/ui/Button.tsx`，默认 `tone="brand"`、`solid`。变体分档与 `app/web/src/ui/Button.tsx` 相同，色调多一档 `brand`，class 用 `classnames` 拼接。尺寸跟壳层主题，和 `app/web` 的按钮同一档：sm / md / lg 高 24 / 30 / 36px，圆角 `--pg-radius-sm` / `md` / `lg`（6 / 8 / 10px），字号 `--pg-font-sm` / `base` / `lg`（12 / 14 / 16px）。页面上的模式、收起、主题用 `sm`（24px / 12px）。顶栏高 40px。`brand` 实底在亮色是 `--pg-brand` 配 `--pg-inverse-text`（白字压 `#6478E8`），悬停 `--pg-brand-600`，按下 `--pg-brand-700`。暗色的 `--pg-brand` 是 `#8492FF`，铺满会在深底上发亮，所以实底改成 `--pg-brand-soft`，字用 `--pg-brand`。悬停把 soft 混进一点 brand。字重 400。`neutral` 的 `solid` 仍用 `--pg-surface-2`，因为亮色里 `--pg-surface` 和页面底同为白色。没有单独的按钮样式表，也没有 `loading`。顶栏切换主题时，壳的 `data-theme` 和 `MdEditor` 的 `theme` 一起变，并记在 `localStorage` 的 `mdplayground.theme`：`dark` 是暗色，其它值、没有这项或读失败时都是亮色。左侧侧栏用 `motion` 改宽度，时长读 `--pg-duration`，叠放用 `--pg-z-fixed`。展开收起记在 `localStorage` 的 `mdplayground.sidebar-open`：`0` 是收起，`1` 是展开，没有这项或读失败时缺省展开。主区域里正文栏由页面决定：宽 `min(760px, calc(100% - 64px))`，水平居中；窄于 700px 时改成 `min(720px, calc(100% - 32px))`。`MdEditor` 铺满这一栏，自己不收 `maxWidth`。当前文档存在 `localStorage` 的 `mdplayground.doc`，值是 `DocJson` 的 JSON。缺键、解析失败，或不是带非空 `content` 的 `doc` 时，用一个空段落。`MdEditor` 从第一帧受控。`onChange` 交出的同一引用写回 state，编辑器会跳过 `setValue`。读写失败就忽略。这里存的是 ProseMirror JSON，不经过 Markdown 转换。

开发命令是根目录的 `pnpm dev:mdplayground`。端口用 Vite 默认值，被占用就顺延。它不进 `pnpm dev`。

## 主题

`MdEditor` 只 `import './styles/base.css'`，不引 `prosemirror-view` 的样式。`base.css` 放两种主题共用的规则：空格、换行、连字、分隔图，以及 `.mded` 和 `.mded.ProseMirror-focused` 的 `outline: none`。会随主题变的值不写在这里。使用方不引 CSS。prop `theme` 是 `'light' | 'dark'`，默认 `'light'`，写到外壳的 `data-theme`。外壳是 `flex min-h-full flex-col`，挂载节点 `flex-1`，让 `.mded` 在父级有高度时铺满。没有第三套主题，也不能注册新主题名。

可选 `themes` 按当前 `theme` 局部覆盖。只把传入的键写成外壳 inline 变量，没传的键仍用样式表里的默认。默认值只在 CSS 里。切换主题不重建 `EditorCore`。占位文案仍是 `--md-editor-placeholder`，不在 token 表里。token 键到变量名的映射在 `src/theme.ts` 的 `themeTokenVars`。`src/theme.test.ts` 断言传入的键会写上、没传的键不出现。

`base.css` 是 Tailwind v4 入口：`@import "tailwindcss" source("..")`，只扫描 `src/`。不建 `tailwind.config.js`。`tailwindcss`（`^4.3.3`）是这个包的依赖。playground 用 `@tailwindcss/vite`（`^4.3.3`）编译组件引入的这份 CSS。同一文件再 `@import "./light.css"` 和 `@import "./dark.css"`。两份都在对应的 `[data-theme]` 上赋值，变量前缀 `--md-editor-`。

token 分组：语义色（含页面底 `--md-editor-bg`、表面、边框、三级文字、品牌、信息、成功、警告、错误和各自的 soft、inverse）、中性色阶、品牌色阶 50–950、圆角、间距、字号阶梯、四档阴影、八档层级、三档时长。圆角、间距、字号、层级、时长和正文字体两边默认相同，仍各写一份。阴影、语义色和品牌色阶 500 及以后两边不同。亮色品牌 500 是 `#6478E8`，暗色是 `#8492FF`。色值来自 `tmp/design-system-preview.html`。这一期不从色阶再推背景、边框、填充。字号阶梯对齐 `app/web` 的同名档：xs 11 / sm 12 / base 14 / lg 16 / xl 20 / 2xl 24，3xl / 4xl 是 24 / 28。圆角 xs / lg / xl 是 4 / 10 / 12px，sm / md 仍是 6 / 8px。

编辑器正文专用、可单边覆盖：`--md-editor-font-family`、`--md-editor-font-size`（`16px`）、`--md-editor-line-height`（`1.6`）、`--md-editor-paragraph-gap`（`12px`）。正文字号 16px，行高 1.6，段距 12px。字体栈仍是系统无衬线。占位色用三级文字，光标用品牌色，选区是品牌色 0.28 透明度，分隔线用默认边框色。暗色正文 `--md-editor-text` 是 `#d8d8d8`，不跟壳层的 `#f1f1f1`，黑底上不发白。亮色仍是 `#171717`。

`.mded` 使用文字、背景、光标、字号、行高、字体，`::selection` 使用选区色，段落使用下边距，空段占位使用占位色，`.mded hr` 是 2px 分隔色，上下边距用 `--md-editor-space-16`（16px）。`.mded ul` 和 `.mded ol` 下边距用段落间距，左内边距 `1.5em`。Tailwind preflight 会把列表标记清掉，所以这里把 `ul` 设回 `disc`、`ol` 设回 `decimal`。圆点和序号用 `li::marker` 取 `--md-editor-brand`，正文仍是 `--md-editor-text`。`.mded li > p` 的下边距是 0，避免每项再叠一段间距。`.mded li` 仍是 `position: relative`。其余变量先定义，后面的块、菜单、浮层再引用。编辑器还没有浮层，层级和时长只放在主题上。

正文内边距写在 `.mded` 上，不进 `themes`。`--md-editor-pad-top` 用 `--md-editor-space-8`（8px），`--md-editor-pad-x` 用 `--md-editor-space-24`（24px），`--md-editor-pad-bottom` 是 24px 的 2 倍（48px）。`box-sizing: border-box`，`min-height: 100%`。栏宽仍由使用方决定，这两层不叠：页边在栏外，这圈在栏内。

`.mded` 行高 `1.6`，`.mded p` 和 `.mded h1`–`h6` 的 margin 都是 `0 0 12px`（`--md-editor-paragraph-gap`）。段与段之间只有这一截下边距，上边距是 0。标题字重 600。字号：`h1` `--md-editor-font-4xl`，`h2` `2xl`，`h3` `xl`，`h4` `lg`，`h5` `base`，`h6` `sm`。`.mded blockquote` 下边距同样是段落间距，左边 3px `--md-editor-brand`，紧挨着的底是 `--md-editor-quote-bg`：亮色纯色 `#f0f1ff`，和 `--md-editor-brand-soft` 相同；暗色透明，只留主题色竖线，内边距上下 `--md-editor-space-8`、左右 `--md-editor-space-16`，字色 `--md-editor-text-2`。引用里最后一块的下边距去掉，避免浅底下面空一截。

tsdown 不处理 CSS。`deps.neverBundle` 里的 `/\.css$/` 让产物保留 `import "./styles/base.css"`，不把 Tailwind 打进 `dist`。构建把 `src/styles/*.css` 抄到 `dist/styles/`，`base.css` 里的相对 `@import` 才能找到主题文件。开发时 Vite 读源码，不走这份拷贝。

包内 `src/css.d.ts` 声明 `declare module '*.css'`，供本包 `tsc` 识别这个 import。没有对外的 CSS export。

## React

`react` 和 `react-dom` 是 peer（`^19`）。tsdown 不把 peer 打进 `dist`。包的 devDependencies 里另有同一主版本和 `@types/react`，供本包 `tsc` 和生成 `.d.ts`。`tsdown.config.mjs` 的 `deps.neverBundle` 列出 `react`、`react-dom`、上面的 ProseMirror 包、`markdown-it`，以及 `/\.css$/`。

构建在共享选项上多了 `platform: 'neutral'` 和 `entry: ['src/index.tsx']`，并保留 `fixedExtension: false`。JSX 用 `react-jsx`。

## 类型检查

消费方 `tsc` 走 `import`，读 `dist`。跑测试页的 `typecheck` 或 `build` 之前，先构建这个包。Vite 开发服务器带 `development` 条件，读 `src/index.tsx`；`optimizeDeps.exclude` 包含 `@relax/md-editor`，改源码会热更新。
