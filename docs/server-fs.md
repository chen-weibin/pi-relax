# 文件系统

`app/server` 对外的文件系统。本文按功能点写当前实现：每个功能点含功能说明、接口说明、使用说明。服务端总览见 [server.md](server.md)。前端插件怎么用见 [web-extension.md](web-extension.md)。

## 公共约定

下面几条所有功能点共用。

- 无鉴权。
- `path` 由调用方传入，必须是绝对路径。服务端不展开 `~`，也没有默认目录。不要求落在某个项目根里，进程能访问的绝对路径都可以。没有路径白名单。
- 查询里的 `path` 做一次 URL 编码。服务端使用解码后的字符串。监听的 `path` 写在 JSON 里，不再编码。
- 失败体是 `{ "error": { "code", "message" } }`。`message` 写具体原因，能带上路径、字节数、上限的都会带上。
- 类型用 `stat`，跟随符号链接。返回里没有单独的「符号链接」类型。链接指向目录就是目录，指向文件就是文件。
- `recursive` 只接受 `true` / `false`。不传或空字符串当作 false。其它值是 400，`recursive 只能是 true 或 false`。
- 阈值在 `config.json` 的 `fs`：`maxBytes` 默认 16777216（16 MiB），`watchDebounceMs` 默认 600，`watchMax` 默认 16。缺字段或不是正整数时用这些默认值。

路径本身不合法时，各接口都是 400：

- 没传或空字符串：`path 必填，且必须是绝对路径`。
- 以 `~` 开头：`path 不能以 ~ 开头，服务端不展开家目录，请传绝对路径`。
- 相对路径：`path 必须是绝对路径：…`。

## 1. 列出一层

### 功能说明

列出一个目录的直接子项，不进入子目录。

每个子项：

| 字段 | 含义 |
| --- | --- |
| `name` | 这一层的名字，例如 `src` |
| `path` | 拼上父目录后的绝对路径，例如父目录是 `/abs/dir` 时为 `/abs/dir/src`。下一步读、写、再列，用这个值 |
| `kind` | `file` 或 `dir`。只看是不是目录。套接字、设备等不是目录的，标成 `file` |
| `size` | 这一项自己的字节数。目录的 `size` 是目录项本身的大小，不是里面文件加总 |
| `mtime` | 修改时间，毫秒，小数丢掉 |

名字不过滤。`.git`、`node_modules`、点文件都会出现。返回前重排：目录在前，文件在后，同一类按 `name` 的 `localeCompare`。这一层全部返回，没有分页，也没有条数上限。

**希望调整（代码还没改）：** 去掉这次重排，按读目录时的顺序返回。也就是 `readdir` 给出的顺序，不再把目录提前，也不再按名字排。等后面和其它调整一起做。

### 接口说明

`GET /api/fs/list`

| 参数 | 必须 | 控制什么 |
| --- | --- | --- |
| `path` | 是 | 要列的那一层。必须是已经存在的目录 |

| 状态码 | 含义 |
| --- | --- |
| 200 | 列出成功。正文是 `{ path, entries }`。空目录的 `entries` 是 `[]` |
| 400 | 路径不合法、`path` 不是目录、路径中有一段不是目录、没有权限 |
| 404 | 路径不存在 |
| 500 | 没有单独对应的文件系统错误 |

### 使用说明

要看一个目录里有什么，把这个目录的绝对路径传给 `path`。成功是 200，正文里的 `path` 就是你传的目录，`entries` 是这一层的子项。现在目录排在文件前面。界面上显示用每一项的 `name`，要点进去继续列、读、写，用该项的 `path`。希望改成按读目录时的顺序返回，见上面「希望调整」。

目录是空的也是 200，`entries` 是空数组。`.git` 和点文件不会被拿掉。子项很多时没有分页，这一层会一次返回。

某一项是指向目录的符号链接时，`kind` 是 `dir`。指向文件则是 `file`。

`path` 指到一个文件上时列不出来，400，提示不是目录。目录不存在是 404，文案是 `路径不存在`。没有单独的「目录不存在」。路径中间某一段是文件，400，提示路径中有一段不是目录。没有权限也是 400，提示没有权限访问。

## 2. 元信息

### 功能说明

看一条路径是文件还是目录，以及它自己的字节数和修改时间。不读正文。目录也可以查。`kind`、`size`、`mtime` 的含义与列出一层的子项相同。

### 接口说明

`GET /api/fs/stat`

| 参数 | 必须 | 控制什么 |
| --- | --- | --- |
| `path` | 是 | 要查的绝对路径。文件和目录都可以，必须已经存在 |

| 状态码 | 含义 |
| --- | --- |
| 200 | `{ kind, size, mtime }` |
| 400 | 路径不合法、路径中有一段不是目录、没有权限 |
| 404 | 路径不存在。文件或目录都是这一条 |
| 500 | 没有单独对应的文件系统错误 |

### 使用说明

打开正文之前，如果只想知道这条路径是文件还是目录、有多大，用这个接口，不要去读文件。一个 12 字节的文件返回 `kind` 为 `file`、`size` 为 12，`mtime` 是毫秒。目录也能查，`kind` 为 `dir`，`size` 是目录项自己的大小，不是里面文件加总。

路径不存在时，不管你以为它是文件还是目录，都是 404，文案都是 `路径不存在`。没有权限是 400。

## 3. 读文件

### 功能说明

读取一个普通文件的正文。正文是原始字节，不是 JSON，也不做 base64。

有两种读法，一次只能用一种。

**整文件。** 不带 `offset`、`length`，也不带 `Range`。HTTP 200。服务端先标 `text` 或 `binary`，`Content-Length` 设成当时的文件大小，再流式吐出。空文件正文为空，标成 `text`。这种读法不看 `fs.maxBytes`。大于 16 MiB 的文件也可以整文件读出。

**读一段。** HTTP 206。区间是闭区间，单位是字节。`length` 是要读的字节数，不是结束下标。`bytes=2-4` 和 `offset=2` 加 `length=3` 读到同一段。请求的长度超过 `fs.maxBytes`（默认 16 MiB）时 413，还没读盘。这里比的是请求里声明的长度，不是文件实际剩下多少。起点还在文件里面、区间越过末尾时，截到最后一个字节，正文可以短于 `length`。

`text` / `binary` 不看扩展名。样本里有字节 0 就是 `binary`；否则整段能按 UTF-8 严格解码才是 `text`。

- 整文件只拿开头最多 8192 字节（8 KiB）做标记，正文仍是整个文件。不超过 8 KiB 就整段判定。超过时，若这 8192 字节已经是合法 UTF-8，标 `text`。若末尾切在一个多字节字符中间（最多认 3 个续字节），丢掉这截残字节再判一次。因此一个汉字正好切在 8 KiB 边界上，仍标 `text`，正文里的汉字是完整的。开头是合法文本、后面才出现字节 0 或非法 UTF-8 时，响应头仍可能是 `text`。
- 分段用这一段实际读到的字节判定，不套 8 KiB 窗口，也不丢掉末尾残字。一段把汉字切成两半，这段标 `binary`。同一文件里另一段若是纯 ASCII，那段标 `text`。分段的标记描述的是这一段。

**希望调整（代码还没改）：** 和列出一层的调整一起做。

1. 整文件读取也看 `fs.maxBytes`。大于上限时，在吐正文之前返回 413，`message` 写明当前字节数和上限。等于上限仍可读。大文件改走分段。
2. 整文件可以在请求头带 `X-Relax-Transfer`。`binary` 不探测内容，响应头就是 `binary`。`text` 要求整段正文都是合法 UTF-8 且没有字节 0，否则 400。不传则仍按现在的规则，看开头最多 8 KiB。
3. 分段固定返回 `binary`，调用方按字节拼接，不要把每一段单独当文本解码。起点还在文件内、区间越过末尾时，继续截到最后一个字节。起点已经在末尾之后仍是 416。一次声明的长度超过 `fs.maxBytes` 仍是 413，不悄悄截成 16 MiB。`Range: bytes=0-` 的剩余部分超过上限时同样 413。

响应头：

| 头 | 值 |
| --- | --- |
| `X-Relax-Transfer` | `text` 或 `binary` |
| `Accept-Ranges` | `bytes` |
| `Content-Type` | `text` 时 `text/plain; charset=utf-8`，`binary` 时 `application/octet-stream` |
| `Content-Length` | 这一次正文的字节数 |
| `Content-Range` | 只有 206 有，形式 `bytes start-end/size`。`start`、`end` 是闭区间，`size` 是读之前看到的文件大小 |

浏览器脚本可以读到 `X-Relax-Transfer`、`Content-Range`、`Accept-Ranges`。

### 接口说明

`GET /api/fs/read`

| 参数 | 位置 | 必须 | 控制什么 |
| --- | --- | --- | --- |
| `path` | 查询 | 是 | 要读的普通文件，必须已存在 |
| `offset` | 查询 | 否 | 这一段的起始字节，从 0 起。和 `length` 成对使用。和 `Range` 二选一 |
| `length` | 查询 | 否 | 这一段要读的字节数，大于 0。和 `offset` 成对使用 |
| `Range` | 请求头 | 否 | 另一种分段写法：`bytes=start-end`，或 `bytes=start-`（从 start 读到文件末尾） |

`offset`、`length` 是非负整数的十进制字符串。空着等于没传。

| 状态码 | 含义 |
| --- | --- |
| 200 | 整文件。正文是原文 |
| 206 | 一段。另有 `Content-Range` |
| 400 | 路径不合法、读的是目录或非普通文件、`offset` 与 `length` 不成对、两种分段一起用、`length` 为 0、`Range` 格式不对、结束位置小于开始位置 |
| 404 | 文件不存在 |
| 413 | 这一段声明的长度超过 `fs.maxBytes`。`code` 为 `PAYLOAD_TOO_LARGE` |
| 416 | 起点在文件末尾之后，或文件是空的还要读一段。`code` 为 `RANGE_NOT_SATISFIABLE` |
| 500 | 整文件流式读开始之后失败。头还没发出去则 500 并结束；头已经发出去则中断这条响应 |

### 使用说明

要读一个普通文本，例如 4 MiB 的 UTF-8 文件，不要带 `offset`、`length`、`Range`。返回 200，`X-Relax-Transfer` 是 `text`，`Content-Type` 是 `text/plain; charset=utf-8`，正文就是文件原文。空文件也是 200，标记为 `text`，正文为空。

文件比 16 MiB 还大，仍然直接整文件读。返回还是 200，正文流式吐出，不会因为体积变成 413。整文件读取不看 `fs.maxBytes`。客户端一次处理不了这么大的正文时，再改成按字节分段，自己用 `offset` 和 `length` 一段段取，或者用请求头 `Range`。

分段时，一次声明的长度不能超过 16 MiB。超过就 413，`code` 是 `PAYLOAD_TOO_LARGE`，提示请求的这一段有多少字节、上限是多少，这一段的内容不会返回。这时把 `length` 改小再请求下一段。文件只有 10 字节、但 `length` 写成 20 MiB，同样 413，不会退回那 10 字节。`Range: bytes=0-` 表示从起点读到文件末尾，文件大于 16 MiB 时也是 413，需要写成带结束位置、并且这一段不超过 16 MiB。

头里是 `binary` 时，这段字节不能按 UTF-8 文本解码，应按原始字节处理。`Content-Type` 是 `application/octet-stream`。文件里有字节 0 就会这样。整文件只看开头 8 KiB 来决定这个头：开头是合法文本、后面才有二进制，头仍可能是 `text`，正文后面的字节还是原样返回。分段时标记只针对这一段。这一段把一个汉字切成两半，这一段的头是 `binary`，把字节拼完整再解码。同一文件里另一段如果是纯 ASCII，那段的头仍是 `text`。

只看文件中间几个字节时用分段。内容是 `abcdefghij` 时，`offset=2` 且 `length=3` 返回 206，正文是 `cde`，`Content-Range` 是 `bytes 2-4/10`。`Range: bytes=2-4` 读到同一段。起点还在文件里、但长度越过末尾，返回 206，正文只到最后一个字节，比 `length` 短。

起点已经超过文件末尾，例如 10 字节的文件从 `offset=20` 读，返回 416，`code` 是 `RANGE_NOT_SATISFIABLE`，提示落在文件末尾之后，并带上文件大小。空文件再读一段也是 416。

`offset` 和 `length` 要一起给，只给一个是 400。它们和 `Range` 也只能留一种，一起给是 400。`length` 为 0 是 400。`Range` 写成 `bytes=-500` 或多段，400，提示只支持 `bytes=start-end` 或 `bytes=start-`。

读目录会 400，提示这是目录，不能读取正文。文件不存在是 404。

上面是当前行为。整文件超过上限要拒绝、整文件可指定 `text` / `binary`、分段固定为 `binary`，见功能说明里的「希望调整」。

## 4. 写文件

### 功能说明

把原始字节写到一个文件。成功时没有响应体。一次正文的上限是 `fs.maxBytes`，默认 16 MiB。超过则 413，已经存在的文件保持原样。

请求头 `X-Relax-Transfer` 声明正文是 `text` 还是 `binary`。`text` 要求整段是合法 UTF-8，且不能含字节 0，否则 400，此时还没替换原文件。`binary` 不检查编码，字节原样落盘。

两种写法：

**不带 `offset`：整文件替换。** 目标已是目录则拒绝。父目录不存在时，只有 `recursive=true` 才把缺的父目录建出来。然后先写同目录临时文件 `{path}.{16位hex}.relax-tmp`，再改名换成目标。同一块盘上，读的人看到旧文件或新文件。临时文件写失败或改名失败时删掉临时文件，原文件还在。进程若在改名之前停掉，目录里可能留下 `.relax-tmp`。目标本来不存在就创建。空正文得到空文件。

**带 `offset`：从该字节写入。** 只接受 `binary`，避免一个字符被切在两次请求中间。直接写在这个位置上，不用临时文件。

- 文件不存在且 `offset` 为 0：创建，内容就是这次正文。
- 文件不存在且 `offset` 大于 0：拒绝。
- `offset` 大于当前长度：拒绝，不会用空字节补出一段空洞。
- `offset` 等于当前长度：追加到末尾。
- `offset` 小于当前长度：从这里覆盖正文那么多个字节。后面没被盖到的字节还在。正文越过旧的末尾时文件变长。这次正文更短，也不会把文件截短。

`Content-Length` 大于上限时，不读正文就 413。没带这个头，或带了但没超过，则边读边累计，累计超过上限再 413，并中止这次请求。413 的文案形如 `这一次写入 N 字节，超过单次上限 M 字节`。

正文不要用 `application/json`。那种类型会先被 JSON 解析吃掉。

### 接口说明

`PUT /api/fs/file`

| 参数 | 位置 | 必须 | 控制什么 |
| --- | --- | --- | --- |
| `path` | 查询 | 是 | 要写的文件。可以尚不存在 |
| `X-Relax-Transfer` | 请求头 | 是 | 声明正文是 `text` 还是 `binary`。带 `offset` 时只能是 `binary` |
| `offset` | 查询 | 否 | 不传则整文件替换。传了则从该字节写入 |
| `recursive` | 查询 | 否 | `true` 时，缺的父目录一并建出。默认不建 |
| `Content-Length` | 请求头 | 否 | 有的话先用它判断这次正文是否超过 `fs.maxBytes` |
| 正文 | 原始字节 | 是 | 要写入的字节。可以是空 |

| 状态码 | 含义 |
| --- | --- |
| 204 | 写完。响应体为空 |
| 400 | 路径不合法、缺少或写错 `X-Relax-Transfer`、用了 `application/json`、`text` 不是合法 UTF-8、目标是目录、带 `offset` 却声明 `text`、`offset` 写出空洞、文件不存在却把 `offset` 设成大于 0、父路径不是目录 |
| 404 | 父目录不存在，且没有 `recursive=true`。文案里的路径是父目录 |
| 413 | 这一次正文超过 `fs.maxBytes`。`code` 为 `PAYLOAD_TOO_LARGE`。原文件不变 |
| 500 | 写入或改名失败，且不属于上面几种 |

### 使用说明

保存一份文本时不要带 `offset`。请求头 `X-Relax-Transfer` 设为 `text`，正文用原始 UTF-8，不要用 `application/json`。正文是「你好」时返回 204，文件内容就是这两个字。4 MiB 的正文也可以一次替换整个文件。

一次正文超过 16 MiB 会失败，返回 413，`code` 是 `PAYLOAD_TOO_LARGE`，提示这一次写入多少字节、上限是多少。磁盘上的旧文件保持不变。改成 `binary` 也绕不过这个上限，二进制同样看 16 MiB。要写更大的文件，改成带 `offset` 分段写，每段不超过 16 MiB。分段时 `X-Relax-Transfer` 必须是 `binary`。声明成 `text` 会 400，提示分段续传只接受 binary，避免一个字符被切在两段中间。

声明了 `text`，但正文里有字节 0，或不是合法 UTF-8，返回 400，提示声明为 text 但正文不是合法 UTF-8。原文件不会被换掉。这种正文改用 `binary` 再写。

不带 `X-Relax-Transfer` 会 400，提示缺少这个请求头。`Content-Type` 用了 `application/json` 也会 400，提示文件正文不要用 JSON，请发送原始字节。

文件还不存在时，不带 `offset` 会创建它。正文为空得到空文件。父目录也不存在时要带 `recursive=true`，缺的父目录会一并建出来，返回 204。不带则 404，文案里的路径是父目录。目标路径已经是目录时 400，提示不能当作文件写入。

按位置改已有内容时带 `offset`，并且用 `binary`。文件还不存在时 `offset` 只能是 0：正文 `ab` 会创建出内容 `ab`。再以 `offset=2` 写入 `cd`，文件变成 `abcd`。再以 `offset=1` 写入 `Z`，文件变成 `aZcd`，只盖住中间那个字节，后面的内容还在。`offset` 等于当前长度就是追加。`offset` 大于当前长度会 400，提示不能写出空洞，文件不变。文件还不存在就把 `offset` 设成大于 0，也会 400。

## 5. 建目录

### 功能说明

新建一层目录。成功时没有响应体。`recursive=true` 时，缺的父目录一并建出；否则父目录必须已经在。路径上已经有文件或目录时拒绝，不会把「已经存在」当成成功。

JSON 正文走 `http.jsonBodyLimit`，默认 1 MiB。建目录的正文远小于这个值。

### 接口说明

`POST /api/fs/dir`，`Content-Type: application/json`。

| 参数 | 必须 | 控制什么 |
| --- | --- | --- |
| `path` | 是 | 要新建的目录的绝对路径 |
| `recursive` | 否 | `true` 时一并建出缺的父目录。默认只建这一层 |

| 状态码 | 含义 |
| --- | --- |
| 204 | 建好。响应体为空 |
| 400 | 路径不合法、路径已存在、`recursive` 的值不对、父路径不是目录、JSON 不合法 |
| 404 | 父目录不存在，且没有 `recursive=true` |
| 500 | 创建失败，且不属于上面几种 |

### 使用说明

在已经存在的父目录下新建一层时，POST `{ "path": "/abs/new-dir" }`。成功 204，出现一个空目录。

父目录也没有时，加上 `"recursive": true`。例如路径是 `/abs/a/b` 而 `/abs/a` 还不存在，`a` 和 `b` 会一起建出来，204。不加 `recursive` 则 404，文案里的路径是那个还不存在的父目录。

这个路径上已经有文件或目录时 400，提示路径已存在，不会当成成功。正文不是合法 JSON 时 400，提示 `Invalid JSON`。

## 6. 删除

### 功能说明

删文件和删目录是两个接口，不能混用。成功时没有响应体。

删文件只接受文件。路径是目录时拒绝，并提示改用删目录。

删目录只接受目录。路径是文件时拒绝，并提示改用删文件。默认只删空目录。`recursive=true` 时，目录和里面的内容一起删。非空又没带 `recursive=true` 时拒绝，目录还在。

### 接口说明

`DELETE /api/fs/file`

| 参数 | 必须 | 控制什么 |
| --- | --- | --- |
| `path` | 是 | 要删的文件 |

`DELETE /api/fs/dir`

| 参数 | 必须 | 控制什么 |
| --- | --- | --- |
| `path` | 是 | 要删的目录 |
| `recursive` | 否 | `true` 时连同里面的内容一起删。默认目录必须为空 |

| 状态码 | 含义 |
| --- | --- |
| 204 | 删掉。响应体为空 |
| 400 | 路径不合法、文件和目录接口用反、目录非空却没带 `recursive=true`、没有权限 |
| 404 | 路径不存在 |
| 500 | 删除失败，且不属于上面几种 |

### 使用说明

删一个文件用 `DELETE /api/fs/file`。成功 204，文件消失。这个接口指到目录上会 400，提示这是目录，请使用删除目录接口，目录还在。

删目录用 `DELETE /api/fs/dir`。空目录直接删，204。里面还有文件时，不带 `recursive` 会 400，提示目录非空，目录和里面的内容都还在。确认要连内容一起删时再加上 `recursive=true`，204，整个目录消失。

把删目录用在文件上会 400，提示这是文件，请使用删除文件接口，文件还在。路径不存在是 404。没有权限是 400。

## 7. 监听

### 功能说明

一条 WebSocket 订阅目录变化。一条连接可以订多个根。没有订阅时不占监听，进程启动时也不扫磁盘。

服务端递归监听调用方给出的那棵目录树，不设深度，也不忽略名字。订阅成功时不补发已经存在的文件。用的是 chokidar，不是 Watchman。

变化先攒在一个窗口里。窗口长度是 `fs.watchDebounceMs`，默认 600 毫秒，从这次窗口里的第一次变化起算，到点就发。窗口里再来的变化不把计时往后推。同一个路径在窗口里出现多次，只留最后一次事件。到点合成一条 `change`。

事件只有 `add`、`change`、`unlink`、`addDir`、`unlinkDir`。其它事件丢掉。`changes[].path` 尽量写成「订阅时那条路径」下面的形式：磁盘真实路径若是符号链接解开后的路径，会换回调用方订阅用的前缀。

路数按根算，不按连接算。根的身份是设备号和 inode。同一目录的两条连接，或 realpath 之后是同一目录的两条路径，只占 1。同时存在的根超过 `fs.watchMax`（默认 16）时，这次订阅失败，已经在听的根还在。某个根的最后一条连接离开，才关掉这路监听。

失败时连接不断。`unwatch` 一个这条连接没订过的路径，不回包。

### 接口说明

`WebSocket /ws/fs`。帧都是 JSON 文本。

客户端：

| 字段 | 必须 | 控制什么 |
| --- | --- | --- |
| `type` | 是 | `watch` 开始监听这个根，`unwatch` 取消 |
| `path` | 是 | 绝对路径。`watch` 时必须是已经存在的目录 |

服务端推送：

| `type` | 含义 |
| --- | --- |
| `watching` | 这个根已经订上。`path` 是调用方传入的那条 |
| `change` | 一个防抖窗口里的变化。`path` 是订阅时的根。`changes` 是 `{ event, path }` 列表 |
| `error` | 这次失败。`path` 是相关路径，JSON 不合法时是空字符串。`error.code` 和 `error.message` 与 HTTP 那套相同 |

这里没有 HTTP 状态码。订不上、消息不合法，都是一条 `error`。

### 使用说明

连上 `/ws/fs` 后发送 `{ "type": "watch", "path": "/abs/project" }`。目录存在时先收到 `watching`，`path` 就是你传的那条。目录里已经有的文件不会补发，之后的变化才会推。

在这个目录里新建 `n.txt`，大约 600 毫秒内收到一条 `change`。`changes` 里 `event` 是 `add`，`path` 是 `/abs/project/n.txt`。改文件内容是 `change`，删文件是 `unlink`，新建目录是 `addDir`，删目录是 `unlinkDir`。这 600 毫秒里同一个文件改了好几次，只会留下最后一次事件，合成一条消息。

同一个目录再 `watch` 一次，还会再收到一条 `watching`，但只占 1 路。另一条连接订同一个目录也只占 1 路，变化两边都会收到。

已经有 16 个不同的根，再订一个新目录，会收到 `error`，提示当前路数和上限。之前订上的还在。`path` 不存在时 `error` 的 `code` 是 `NOT_FOUND`。`path` 是文件时提示不是目录。

不再需要时发送 `{ "type": "unwatch", "path": "/abs/project" }`。如果这是这个根的最后一条连接，之后不再推送，也没有成功帧。连接直接关掉效果一样，这路监听会释放。
